1. **Exact working title:** *SecretHandle: OS-Minted, Destination-Bound Opaque Secrets for Mobile AI Agents*.
2. **Core field:** mobile systems security, Android OS mechanisms, and security/privacy for GUI-operating AI agents.
3. **Core technical keywords:** SecretHandle; mobile AI agent; Android; OS-minted opaque capability; authoritative secret source; destination binding; task binding; OTP; Credential Manager; clipboard; wallet; accessibility; prompt injection; redirection; replay; observation redaction; StrongBox; typed lifecycle.

5. **Main mathematical objects:** a secret value; a randomized opaque handle; secret type; source identity; package/origin/field destination predicate; task identifier; issue and expiry times; use budget; confirmation policy; authenticated handle record; agent-visible observation; target UI node; mint, enter/resolve, redact, expire, and revoke transitions; confidentiality, destination-safety, unforgeability, replay-safety, and utility properties.
6. **Proposed algorithm/system name:** SecretHandle. The central agent action is `ENTER(handle)`.
7. **Theorem directions:** the concept document does not state formal named theorems. It implies conditional guarantees for (i) value non-disclosure to the agent, (ii) rejection at non-bound destinations, (iii) unforgeability of OS capabilities, (iv) single-use/TTL replay resistance, and (v) post-entry non-observation, all under explicit trusted-OS and cryptographic assumptions. These are safety properties, not universal end-to-end security claims.

9. **Baselines:** unprotected accessibility agent; detector/screen-scraped placeholders (especially the cited 2602.10139 concept, if independently verified); AutoDroid-style substitution; Android Autofill/Credential Manager where invocable. Tool-agent isolation or information-flow systems are related work, not interchangeable empirical baselines.
10. **Seed references and sources:** AutoDroid (MobiCom 2024); CaMeL (arXiv:2503.18813); FIDES (arXiv:2505.23643); Dual LLM pattern; AirGapAgent (CCS 2024); IsolateGPT (NDSS 2025); Progent (arXiv:2504.11703); HaS; Casper; Rescriber; PAPILLON; PrivacyRestore; EIA (ICLR 2025); fine-print injection (arXiv:2504.11281); the mobile-agent OTP attack identified as arXiv:2510.27140; Brave's Comet incident report; Android platform documentation; AP2/payment-token sources; OAuth resource indicators (RFC 8707); mobile-agent benchmarks and systems named in the evaluation plan. Every item must be resolved and verified before substantive citation.
11. **Explicit assumptions and risks:** trusted, uncompromised OS and mint/resolver/redactor; authentic destination identity; secure key storage; complete redaction on both accessibility trees and pixels; careful WebView-origin attribution; source authenticity for OTPs; no raw-value side channel outside modeled observations; confirmation availability for payment handles; detector-free security only for values integrated at authoritative sources. Residual semantic attacks can induce legitimate but unwanted actions within an allowed destination. Existing placeholder/autofill work may narrow novelty. No real evaluation results or AOSP implementation currently exist.
12. **What the paper is not about:** federated learning, over-the-air aggregation, differential privacy, blockchains, incentive/mechanism design, general LLM alignment, server-side payment-token protocols as the main contribution, generic prompt sanitization, or a claim that all prompt injection is prevented.

## LOCKED PAPER SPECIFICATION

- **Locked topic:** an Android OS data-isolation mechanism that lets untrusted mobile AI agents use sensitive values through OS-minted, opaque, destination- and task-bound capabilities without observing the raw values.
- **Locked problem statement:** prevent disclosure, redirection, forgery, replay, and post-entry re-observation of OTPs, credentials, identifiers, clipboard values, and payment identifiers while preserving legitimate login, 2FA, and checkout completion.
- **Locked method family:** OS capability design and enforcement spanning authoritative-source minting, authenticated handle metadata, destination-aware resolution in the input/accessibility path, typed lifecycle policy, hardware-backed keys, optional user confirmation, and observation-side redaction.
- **Locked theoretical goals:** precisely model the transition system and prove conditional safety properties for agent non-disclosure, destination confinement, handle unforgeability, replay limits, and redaction closure. No proof may exceed the stated OS, cryptographic, and observation assumptions.
- **Locked experiment family:** AOSP/mobile-device evaluation on real or open test flows, mobile GUI agents, injection/redirection/replay/forgery/reread attacks, latency and task-success measurements, and component ablations. ## Fidelity decision

The manuscript may formalize and expand the mechanism, but it may not claim an implemented prototype, measured result, exhaustive novelty, or empirical superiority until those artifacts exist. The formal results must be framed as properties of the specified model, not evidence that an unimplemented Android system already satisfies them.
