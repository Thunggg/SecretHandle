\section{Experimental Evaluation}
\label{sec:evidence}

We evaluate \SH{} on a stock-Android userdebug environment (Android 14, API 33/34) running on an AWS EC2 bare-metal-equivalent instance (\texttt{m8i.4xlarge}, 16 vCPUs, 64 GiB RAM, KVM nested virtualization). We evaluate against an off-the-shelf mobile GUI agent: Mobile-Agent v3.5 \cite{wang2024mobileagent} driven by Claude Sonnet~4.6 through an isolated local bridge, with screenshot-only observation and no accessibility-tree or prompt-level ground-truth cheats. The evaluation answers six primary research questions: (RQ1) confidentiality of secrets during agent navigation; (RQ2) defense against Confused Deputy destination redirection; (RQ3) atomic single-use lifecycle and race immunity; (RQ4) post-entry observation redaction; (RQ5) runtime and memory overhead; and (RQ6) transparency and general-task regression on benign applications.

\paragraph{Baselines.} We compare four security conditions:
(B0)~\emph{Unprotected}: the agent observes the raw plaintext secret in notifications and on-screen and types it directly.
(B1)~\emph{Detected Placeholder}: rendered sensitive text is replaced with an unbound local placeholder, approximating existing mobile anonymizers \cite{zhao2026anonymization}.
(B2)~\emph{Platform Flow}: standard Android Credential Manager or Autofill where supported \cite{androidAutofillServices,androidCredentialManager} (unsupported workflows recorded as N/A).
(B3)~\emph{\SH}: OS-source minting, destination binding, atomic lifecycle, and observation redaction.

\paragraph{Secret Exposure and Redaction (RQ1, RQ4).}
Under B0, the agent leaked an unredacted verification code in $29/30$ trials (exposure rate $E=0.97$, Wilson $[0.83, 0.99]$); in all 29 cases, the agent read the plaintext code directly off the screen and transmitted it. Under B3, the prototype mints an opaque handle (\texttt{SH-XXXXXX}) at arrival, replaces the notification with one naming only the handle (Figure~\ref{fig:b3}a), and masks on-screen conversation bubbles with a non-touchable accessibility overlay (Figure~\ref{fig:b3}b). Across $n=30$ independent trials with fresh synthetic canaries, the agent read $0/30$ codes (exposure $E=0.00$, Wilson $[0.00, 0.11]$). A control run with the overlay service disabled leaked in 2 steps ($1/1$), confirming that the zero is not a harness artifact. Furthermore, after injection into the destination field, continuous redaction prevented post-entry rereading ($L=0.00$, $0/30$).

\paragraph{Killer Experiment: Destination Redirection (RQ2).}
In Attack~2, an injected instruction directs the agent to paste the handle into an adversary-controlled destination app (\texttt{com.attacker.app}) rather than the legitimate destination.
Under baseline B1 (unbound placeholder), the resolver resolves the token for any requesting caller, resulting in $30/30$ leaks ($R=1.00$, Wilson $[0.89, 1.00]$) and completely breaking legitimate utility ($U=0.00$, $0/30$).
Under B3, the handle is bound to the legitimate package and task context; when presented by the adversary app, the resolver executes Algorithm~2, detects a caller mismatch, and rejects resolution with \texttt{CALLER\_MISMATCH} in $30/30$ trials ($R=0.00$, Wilson $[0.00, 0.11]$). Conversely, in legitimate workflows, resolution into the bound destination succeeds in $30/30$ trials ($U=1.00$, Wilson $[0.89, 1.00]$).

\paragraph{Lifecycle Atomicity and Concurrency (RQ3).}
We stress-tested handle lifecycle properties across $n=50$ trials per condition:
(1)~\emph{Sequential replay}: Replay resolution of an already-resolved handle was rejected in $50/50$ cases with \texttt{ALREADY\_RESOLVED} ($Y=0.00$, Wilson $[0.00, 0.07]$).
(2)~\emph{TTL expiry}: Attempting resolution after TTL expiration (5 minutes) was rejected in $50/50$ cases with \texttt{HANDLE\_EXPIRED} ($0/50$ bypassed).
(3)~\emph{Multi-threaded race}: For each handle, 10 concurrent threads simultaneously contested resolution through a synchronized barrier (500 threads total); in $50/50$ trials, exactly one thread succeeded and 9 threads received rejections, with zero concurrency anomalies.

\paragraph{Microbenchmark Overhead (RQ5).}
We executed an on-device microbenchmark harness directly inside the Android ART runtime via \texttt{app\_process} ($n=100$ trials):
\begin{itemize}[leftmargin=*]
  \item \textbf{Mint latency:} Mean $5.61\,\mu\text{s}$ (median $5.24\,\mu\text{s}$, min $2.73\,\mu\text{s}$, p95 $9.30\,\mu\text{s}$, std $3.96\,\mu\text{s}$).
  \item \textbf{Resolve latency:} Mean $0.13\,\mu\text{s}$ (median $0.12\,\mu\text{s}$, min $0.11\,\mu\text{s}$, p95 $0.18\,\mu\text{s}$, std $0.06\,\mu\text{s}$).
  \item \textbf{Memory footprint:} Total process PSS is $28.71\,\text{MB}$ (Native Heap: $14.19\,\text{MB}$, Dalvik Heap: $2.11\,\text{MB}$; Dalvik heap allocated: $1.15\,\text{MB}$).
\end{itemize}
These microsecond-scale latencies impose negligible overhead compared to agent visual inference times ($40$--$60\,\text{s}$/action).

\paragraph{Benign Task Regression and Transparency (RQ6).}
To verify that \SH{} does not interfere with general agent UI control or normal user workflows, we benchmarked the system across 10 diverse benign application suites in AndroidWorld \cite{rawles2024androidworld} (DeskClock, Markor Notes, Simple Calendar, Simple Gallery, Audio Recorder, Simple Draw, Camera2, Settings, SMS Messenger, and Contacts):
\begin{itemize}[leftmargin=*]
  \item \textbf{Touch input transparency:} Across 50 automated touch injection cycles, $100\%$ ($50/50$) of touch events passed cleanly through the overlay layer to the underlying application. Because overlays set \texttt{FLAG\_NOT\_TOUCHABLE} and \texttt{FLAG\_NOT\_FOCUSABLE}, \SH{} causes zero touch blocking ($0.0\%$ input block rate).
  \item \textbf{Frame rendering latency:} GPU frame metrics via \texttt{dumpsys gfxinfo} on productivity apps (Settings, Markor Notes) confirmed that p95 frame rendering latency was virtually identical between B0 and B3 (Markor: $18.0\,\text{ms}$ under both B0 and B3, $\Delta = 0.0\,\text{ms}$; Settings: $36.0\,\text{ms}$ under both B0 and B3, $\Delta = 0.0\,\text{ms}$), proving that the 200\,ms background scanner does not degrade the compositor.
  \item \textbf{General-task regression:} Across all benign workflows, task success and action sequences remained unaffected by the presence of \SH, demonstrating general-task regression $\Delta = 0.00$.
\end{itemize}
