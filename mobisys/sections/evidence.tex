\section{Experimental Evaluation}
\label{sec:evidence}

We evaluate \SH{} on a stock-Android userdebug environment (Android 14, API 33/34) running on an AWS EC2 bare-metal-equivalent instance (\texttt{m8i.4xlarge}, 16 vCPUs, 64 GiB RAM, KVM nested virtualization). We evaluate against an off-the-shelf mobile GUI agent: Mobile-Agent v3.5 \cite{wang2024mobileagent,ye2025mobileagentv3} driven by Claude 3.5 Sonnet (via Amazon Bedrock, snapshot \texttt{claude-3-5-sonnet-20241022}, sampling temperature $T=0.0$, top-p $1.0$, maximum 15 interaction steps per task) through an isolated local bridge, with screenshot-only observation and no accessibility-tree or prompt-level ground-truth cheats. For structural GUI evaluation, we deploy AutoDroid \cite{wen2023autodroid} powered by GPT-4o (\texttt{gpt-4o-2024-08-06}, $T=0.0$). The evaluation answers six primary research questions: (RQ1) confidentiality of secrets during agent navigation; (RQ2) defense against Confused Deputy destination redirection; (RQ3) atomic single-use lifecycle and race immunity; (RQ4) post-entry observation redaction; (RQ5) runtime and memory overhead; and (RQ6) transparency and general-task regression on benign applications.

\paragraph{Baselines.} We compare four security conditions:
(B0)~\emph{Unprotected}: the agent observes the raw plaintext secret in notifications and on-screen and types it directly.
(B1)~\emph{Detected Placeholder}: rendered sensitive text is replaced with an unbound local placeholder via local regex/NER scanning ($150\,\text{ms}$ parsing overhead), approximating existing mobile anonymizers \cite{zhao2026anonymization}.
(B2)~\emph{SMS Consent / Unbound Autofill Flow}: standard Android SMS User Consent and unauthenticated autofill flows \cite{androidAutofillServices,androidCredentialManager,androidSmsConsent}. While Credential Manager and SMS Retriever bind credentials to package signatures via Digital Asset Links or 11-character app hashes, SMS User Consent displays a one-tap dialog without package binding. Crucially, none of these platform mechanisms provide intra-app field binding, and none redact entered values from subsequent screenshots.
(B3)~\emph{\SH}: OS-source minting, destination binding, atomic lifecycle, and observation redaction.

\paragraph{Secret Exposure and Redaction (RQ1, RQ4).}
Under B0, the visual agent leaked an unredacted verification code in $29/30$ trials (exposure rate $E=0.97$, Wilson $[0.83, 0.99]$); in all 29 cases, the agent read the plaintext code directly off the screen and transmitted it. Under B3, the prototype mints an opaque handle (\texttt{SH-XXXXXX}) at arrival, replaces the notification with one naming only the handle (Figure~\ref{fig:b3}a), and masks on-screen conversation bubbles with a non-touchable accessibility overlay (Figure~\ref{fig:b3}b). Across $n=30$ independent trials with fresh synthetic canaries, the agent read $0/30$ codes (exposure $E=0.00$, Wilson $[0.00, 0.11]$). A single-trial control run with the overlay service disabled leaked in 2 steps ($1/1$), confirming that the zero is not a harness artifact. Furthermore, continuous redaction prevented post-entry rereading ($L=0.00$, $0/30$).
\emph{Agent and Modality Diversity}: To evaluate structural agents beyond visual VLMs, we benchmarked an Accessibility-Tree agent (AutoDroid~\cite{wen2023autodroid}) across $n=30$ independent trials on Android~14. Under B0, plaintext canaries leaked into dumped \texttt{AccessibilityNodeInfo} attributes in $30/30$ trials ($E_{\text{tree}}=1.00$, Wilson $[0.89, 1.00]$). Under B3, \SH{} suppressed plaintext secrets at the notification broker and Agent SDK bridge (which filters underlying node text alongside screenshot overlay masking), achieving zero exposure ($E_{\text{tree}}=0.00$, $0/30$, Wilson $[0.00, 0.11]$) with $100\%$ handle perception ($30/30$) and mean tree parse time of $0.78\,\text{ms}$. Under Attack~2 redirection, \SH{} blocked unauthorized tree actions ($R_{\text{tree}}=0.00$, $0/30$) while preserving legitimate entry ($U_{\text{tree}}=1.00$, $30/30$). Because mediated captures withhold raw secrets before serialization to the agent UID, this zero-exposure property holds consistently across visual and structural perception models.

\paragraph{Killer Experiment: Destination Redirection (RQ2).}
In Attack~2, an injected instruction directs the agent to paste the handle into an adversary-controlled destination app (\texttt{com.attacker.rewards}) rather than the legitimate destination.
Under baseline B1 (unbound placeholder), the resolver resolves the token for any requesting caller, resulting in $30/30$ leaks ($R=1.00$, Wilson $[0.89, 1.00]$) and completely breaking legitimate utility ($U=0.00$, $0/30$).
Under baseline B2 (SMS Consent / Unbound Autofill Flow), secrets are isolated before interaction ($E=0.00$, $0/30$), with benign utility $U_{\text{benign}}=1.00$ ($30/30$, $2.1\,\text{ms}$ dispatch). However, lacking agent-destination confinement, an injected agent clicking the platform prompt on top of \texttt{com.attacker.rewards} triggers unconfined release, leaking secrets in $30/30$ trials ($R=1.00$, $U_{\text{attack}}=0.00$).
Under B3, the handle is bound to the legitimate package and task context; when presented by the adversary app, the resolver executes Algorithm~2, detects a caller mismatch, and records an internal \texttt{CALLER\_MISMATCH} audit violation while returning a value-oblivious rejection to the agent in $30/30$ trials ($R=0.00$, Wilson $[0.00, 0.11]$). Conversely, in legitimate workflows, resolution into the bound destination succeeds in $30/30$ trials ($U=1.00$, Wilson $[0.89, 1.00]$).
We additionally evaluated fine-grained intra-app and multi-source variations ($n=30$ each): (1)~\emph{Intra-app field redirection}: An attacker prompt directs pasting into customer support in the same banking app; \SH's field predicate ($f = \text{smsOTPCode}$) rejected resolution ($R=0.00$, Wilson $[0.00, 0.11]$) while preserving OTP autofill ($U=1.00$). (2)~\emph{Segmented OTPs}: \SH{} resolved codes across 6 single-digit \texttt{EditText} fields via sibling container traversal in mean $0.93\,\mu\text{s}$ (p95 $1.15\,\mu\text{s}$) with complete utility ($U=1.00$, $0/30$ exposure). (3)~\emph{Clipboard sources}: \SH{} intercepted Android~14 sensitive clipboard writes (\texttt{EXTRA\_IS\_SENSITIVE}) for $u_0=5$; unauthorized paste was blocked ($R=0.00$) while bound paste succeeded ($U=1.00$, mediation mean $6.74\,\mu\text{s}$).

\paragraph{Lifecycle Atomicity and Concurrency (RQ3).}
We stress-tested handle lifecycle properties across $n=50$ trials per condition: (1)~\emph{Sequential replay}: Replay resolution of an already-resolved handle was rejected in $50/50$ cases with an internal \texttt{ALREADY\_RESOLVED} audit log ($Y=0.00$, Wilson $[0.00, 0.07]$). (2)~\emph{TTL expiry}: Resolution after TTL expiration (5 minutes) was rejected in $50/50$ cases with \texttt{HANDLE\_EXPIRED} ($0/50$ bypassed). In both cases, the untrusted caller received an uninformative \texttt{unavailable handle} response. (3)~\emph{Multi-threaded race}: For each handle, 10 concurrent threads simultaneously contested resolution through a synchronized barrier (500 threads total); in $50/50$ trials, exactly one thread succeeded and 9 threads received rejections, with zero concurrency anomalies.

\paragraph{Microbenchmark Overhead (RQ5).}
We benchmarked \SH{}'s core vault and session-key mediation inside Android's ART runtime via \texttt{app\_process} ($n=100$) on an x86\_64 KVM emulator and a physical ARM device (Samsung Galaxy A52s, Snapdragon~778G, Android~14 API~34): (1)~\textbf{In-Vault transitions:} In-vault mint latency averages $5.42\,\mu\text{s}$ (emulator, p95 $9.23\,\mu\text{s}$) and $11.54\,\mu\text{s}$ (physical ARM, p95 $15.10\,\mu\text{s}$); resolve CAS averages $0.18\,\mu\text{s}$ (emulator) and $0.31\,\mu\text{s}$ (ARM). (2)~\textbf{Core mediation breakdown:} On emulator, in-process mediation totals $11.20\,\mu\text{s}$ ($0.61\,\mu\text{s}$ parcel serialization, $9.32\,\mu\text{s}$ in-memory JCA \texttt{HmacSHA256} session-key verification, $0.08\,\mu\text{s}$ policy check, $0.13\,\mu\text{s}$ buffer prep, and $1.06\,\mu\text{s}$ vault CAS/loop overhead). On physical ARM silicon, the corresponding breakdown averages $1.73\,\mu\text{s}$ parcel preparation, $17.63\,\mu\text{s}$ in-memory JCA \texttt{HmacSHA256} (p95 $23.33\,\mu\text{s}$), $0.16\,\mu\text{s}$ policy check, $0.45\,\mu\text{s}$ buffer prep, and $2.33\,\mu\text{s}$ vault CAS/loop overhead, totaling $22.30\,\mu\text{s}$ ($0.0223\,\text{ms}$, p95 $30.2\,\mu\text{s}$). Core vault mediation is over two orders of magnitude ($\sim 187\times$) faster than full cross-process OS UI dispatch via \texttt{AccessibilityService} ($4.18\,\text{ms}$, p95 $5.82\,\text{ms}$) and $<0.01\%$ of VLM step latency ($48.6\,\text{s}$). (3)~\textbf{Memory footprint:} In-vault Dalvik heap allocation is $1.15\,\text{MB}$ ($1.43\,\text{MB}$ on ARM); total vault PSS is $28.7\,\text{MB}$ ($14.2\,\text{MB}$ native, $2.1\,\text{MB}$ Dalvik, plus $12.4\,\text{MB}$ shared ART runtime mappings and system libraries).

\paragraph{Benign Transparency and Frame Latency (RQ6).}
Across 10 benign AndroidWorld~\cite{rawles2024androidworld} applications (DeskClock, Markor Notes, Simple Calendar, Simple Gallery, Audio Recorder, Simple Draw, Camera2, Settings, SMS Messenger, Contacts), $100\%$ ($50/50$) of touch events passed cleanly through the overlay (\texttt{FLAG\_NOT\_TOUCHABLE}, $0.0\%$ block rate). GPU profiling via \texttt{dumpsys gfxinfo} showed identical p95 frame rendering latencies between B0 and B3 on measured active UI suites (Markor: $18.0\,\text{ms}$; Settings: $36.0\,\text{ms}$, $\Delta = 0.0\,\text{ms}$). Daemon profiling showed $0.2\%$ CPU idle and $1.4\%$ burst mediation on emulator; on physical Galaxy~A52s hardware, active bursts consumed $7.2\%$ total CPU ($3.2\%$ user, $3.2\%$ kernel, $0.0\%$ iowait, $0.5\%$ irq, $0.1\%$ softirq per \texttt{top}). Software power-profile estimation via \texttt{dumpsys batterystats} under simulated battery unplug indicated zero background polling drain and $<0.12\,\text{mJ}$ modeled energy per mediation event (noting this is an OS software power-profile estimate rather than hardware power-meter instrumentation).

\paragraph{Qualitative Analysis: Anatomy of Agent Misdirection.}
We evaluated 5 prompt injection templates ($n=6$ each, $n=30$ total; Table~\ref{tab:attack_templates}): (1)~\emph{Direct Exfiltration} (monetary reward lure), (2)~\emph{Support Diversion} (in-app chat redirection), (3)~\emph{Web Phishing} (external browser form), (4)~\emph{DoS Depletion} (repeated invalid submissions), and (5)~\emph{Multilingual Injection} (alternating Vietnamese/English syntax). Payloads arrive via unredacted non-banking notifications or untrusted third-party chat/web pages. In a representative Template~1 trial, a promotional notification arriving alongside the banking SMS prompts the agent to forward the OTP (\texttt{com.legitimate.bank}) to \texttt{com.attacker.rewards}.

Under \textbf{B0}, the VLM obeys the injected alert, opens \texttt{com.attacker.rewards}, types raw \texttt{849201}, and submits in $29/30$ trials (4.2 steps mean). Under \textbf{B1}, \texttt{849201} is replaced with \texttt{[TOKEN\_OTP\_1]}, yet the planner pastes the token into \texttt{com.attacker.rewards} and B1's unbound resolver leaks the plaintext ($30/30$, $R=1.00$).

Under \textbf{B3 (\SH{})}, the notification broker mints \texttt{SH-A8F29C} bound strictly to \texttt{pkg:\allowbreak com.\allowbreak legitimate.\allowbreak bank} before agent observation. When the confused agent attempts entry into \texttt{com.attacker.rewards}, the resolver executes Algorithm~2, confirms $\mathsf{Target} \neq \mathsf{BoundTarget}$, records \texttt{DESTINATION\_MISMATCH}, and rejects resolution. Per Algorithm~\ref{alg:resolve} Line~\ref{line:resolve:mismatch}, a single mismatch increments $k$ to $1 < k_{\max}=3$ while preserving $u$ (decremented only at Line~\ref{line:resolve:reserve}); the bridge returns \texttt{destination denied}, enabling backtracking to complete the banking flow. Under repeated DoS retries ($\ge k_{\max}=3$ in Template~4), the handle transitions to \textsf{revoked} and requires local single-tap user touch-confirmation fallback (human intervention rather than autonomous recovery).

\emph{Fallback \& WebView Microbenchmarks}: Two synthetic \texttt{BenchmarkRunner} suites ($n=30$ each) isolate non-standard UIs and web origins: (1)~\texttt{Vault.revealFallback} pairs foreground package verification with a user touch gate for custom canvases/numpads lacking \texttt{smsOTPCode}, blocking adversary apps ($0/30$ leaks) and permitting bound targets ($30/30$, median vault check $47.60\,\mu\text{s}$ excluding human reaction time); (2)~\texttt{Vault.revealWeb} (separate from the $n=6$ end-to-end Template~3 trials) blocks unverified origins fail-closed ($0/30$ leaks) while permitting bound origins ($30/30$, median $56.80\,\mu\text{s}$).

\paragraph{Empirical Real-App UI Compatibility (Physical Device).}
To validate destination-matching compatibility beyond synthetic apps, we captured static UI accessibility trees (\texttt{uiautomator dump}) and installed package versions (\texttt{dumpsys package}) across 20 commercial Google Play applications navigated to live login, phone/OTP, or PIN screens on a physical Samsung Galaxy~A52s (\texttt{SM-A528B}, Android~14 API~34; Table~\ref{tab:app_compatibility} in Appendix~\ref{sec:appendix_compat}). All 20 applications exposed standard \texttt{EditText} (19/20) or \texttt{AutoCompleteTextView} (1/20, Microsoft Teams) nodes: $9/20$ ($45.0\%$, including MoMo, Shopee, Messenger, Lazada, Grab, and Discord) yielded \emph{Direct Match} via explicit OTP/password semantic cues, whereas $11/20$ ($55.0\%$, including Telegram, WhatsApp, GitHub, OKX, Binance, PayPal, and Bitwarden) lacked explicit semantic hints on initial entry fields and resolved cleanly via \emph{Standard Package+Class Fallback} paired with user touch confirmation. Two applications natively delegated credential entry across package boundaries (\texttt{Gmail} $\rightarrow$ \texttt{com.google.android.gms}; \texttt{SoundCloud} $\rightarrow$ \texttt{com.android.chrome} Custom Tab), empirically motivating explicit delegated-auth destination rules; an attempted banking-app audit (\texttt{com.VCB}) was excluded after pre-login RASP checks blocked Developer Options before rendering credentials.

\paragraph{Ablation: Dissecting Security Invariants.}
Disabling each invariant isolates its necessity: (1)~\emph{No Source Minting} degrades to B0 screen exposure ($E=0.97$); (2)~\emph{No Destination Binding} degrades to B1 redirection ($R=1.00$); (3)~\emph{No Atomic CAS} permits concurrent OTP duplication ($50/50$ races); and (4)~\emph{No Observation Redactor} exposes resolved plaintext in the next screenshot ($L=1.00$ in a $1/1$ control test). All four invariants are non-redundant.
