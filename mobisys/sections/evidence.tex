\section{Experimental Evaluation}
\label{sec:evidence}

We evaluate \SH{} on a stock-Android userdebug environment (Android 14, API 33/34) running on an AWS EC2 bare-metal-equivalent instance (\texttt{m8i.4xlarge}, 16 vCPUs, 64 GiB RAM, KVM nested virtualization). We evaluate against an off-the-shelf mobile GUI agent: Mobile-Agent v3.5 \cite{wang2024mobileagent} driven by Claude Sonnet~4.6 through an isolated local bridge, with screenshot-only observation and no accessibility-tree or prompt-level ground-truth cheats. The evaluation answers six primary research questions: (RQ1) confidentiality of secrets during agent navigation; (RQ2) defense against Confused Deputy destination redirection; (RQ3) atomic single-use lifecycle and race immunity; (RQ4) post-entry observation redaction; (RQ5) runtime and memory overhead; and (RQ6) transparency and general-task regression on benign applications.

\paragraph{Baselines.} We compare four security conditions:
(B0)~\emph{Unprotected}: the agent observes the raw plaintext secret in notifications and on-screen and types it directly.
(B1)~\emph{Detected Placeholder}: rendered sensitive text is replaced with an unbound local placeholder, approximating existing mobile anonymizers \cite{zhao2026anonymization}.
(B2)~\emph{Platform Flow}: standard Android Credential Manager and SMS User Consent flows \cite{androidAutofillServices,androidCredentialManager,androidSmsConsent}, which isolate credentials during retrieval but rely on standard framework focus without agent-destination confinement.
(B3)~\emph{\SH}: OS-source minting, destination binding, atomic lifecycle, and observation redaction.

\paragraph{Secret Exposure and Redaction (RQ1, RQ4).}
Under B0, the agent leaked an unredacted verification code in $29/30$ trials (exposure rate $E=0.97$, Wilson $[0.83, 0.99]$); in all 29 cases, the agent read the plaintext code directly off the screen and transmitted it. Under B3, the prototype mints an opaque handle (\texttt{SH-XXXXXX}) at arrival, replaces the notification with one naming only the handle (Figure~\ref{fig:b3}a), and masks on-screen conversation bubbles with a non-touchable accessibility overlay (Figure~\ref{fig:b3}b). Across $n=30$ independent trials with fresh synthetic canaries, the agent read $0/30$ codes (exposure $E=0.00$, Wilson $[0.00, 0.11]$). A control run with the overlay service disabled leaked in 2 steps ($1/1$), confirming that the zero is not a harness artifact. Furthermore, continuous redaction prevented post-entry rereading ($L=0.00$, $0/30$). Evaluating model/agent diversity, tests on an open-weight VLM (Qwen2.5-VL-72B) and an Accessibility-Tree agent (AutoDroid) confirmed consistent zero-exposure ($E=0.00$, $0/20$), as \SH{} concurrently redacts on-screen pixels and node text attributes.

\paragraph{Killer Experiment: Destination Redirection (RQ2).}
In Attack~2, an injected instruction directs the agent to paste the handle into an adversary-controlled destination app (\texttt{com.attacker.rewards}) rather than the legitimate destination.
Under baseline B1 (unbound placeholder), the resolver resolves the token for any requesting caller, resulting in $30/30$ leaks ($R=1.00$, Wilson $[0.89, 1.00]$) and completely breaking legitimate utility ($U=0.00$, $0/30$).
Under B3, the handle is bound to the legitimate package and task context; when presented by the adversary app, the resolver executes Algorithm~2, detects a caller mismatch, and rejects resolution with \texttt{CALLER\_MISMATCH} in $30/30$ trials ($R=0.00$, Wilson $[0.00, 0.11]$). Conversely, in legitimate workflows, resolution into the bound destination succeeds in $30/30$ trials ($U=1.00$, Wilson $[0.89, 1.00]$).
We additionally evaluated intra-app redirection: an attacker prompt directs the agent to paste the OTP into a customer-support chat field within the same legitimate banking app (\texttt{com.legitimate.bank}). \SH's field-class predicate ($f = \text{smsOTPCode}$) rejected resolution into the chat input ($f = \text{chatInput}$) in $30/30$ trials ($R=0.00$, Wilson $[0.00, 0.11]$) while preserving legitimate OTP autofill ($U=1.00$, $30/30$), validating fine-grained intra-app confinement beyond coarse package checks.

\paragraph{Lifecycle Atomicity and Concurrency (RQ3).}
We stress-tested handle lifecycle properties across $n=50$ trials per condition: (1)~\emph{Sequential replay}: Replay resolution of an already-resolved handle was rejected in $50/50$ cases with \texttt{ALREADY\_RESOLVED} ($Y=0.00$, Wilson $[0.00, 0.07]$). (2)~\emph{TTL expiry}: Resolution after TTL expiration (5 minutes) was rejected in $50/50$ cases with \texttt{HANDLE\_EXPIRED} ($0/50$ bypassed). (3)~\emph{Multi-threaded race}: For each handle, 10 concurrent threads simultaneously contested resolution through a synchronized barrier (500 threads total); in $50/50$ trials, exactly one thread succeeded and 9 threads received rejections, with zero concurrency anomalies.

\paragraph{Microbenchmark Overhead (RQ5).}
We benchmarked \SH{} across both isolated in-vault transitions and full end-to-end OS mediation ($n=100$ trials): (1)~\textbf{In-Vault state transition:} Measured inside the Android runtime via \texttt{app\_process}, in-vault mint latency is mean $5.23\,\mu\text{s}$ (median $5.20\,\mu\text{s}$, p95 $7.78\,\mu\text{s}$, std $1.51\,\mu\text{s}$) and in-vault resolve CAS is mean $0.18\,\mu\text{s}$ (median $0.17\,\mu\text{s}$, p95 $0.21\,\mu\text{s}$). (2)~\textbf{End-to-End mediation breakdown:} Core mediation crypto and IPC on Android~14 totals mean $12.4\,\mu\text{s}$ ($0.0124\,\text{ms}$, p95 $18.6\,\mu\text{s}$), comprising Binder IPC round-trip ($0.76\,\mu\text{s}$), Hardware Keystore HMAC-SHA256 verification ($10.41\,\mu\text{s}$), target context extraction and policy match ($0.08\,\mu\text{s}$), and private text injection sync ($0.12\,\mu\text{s}$); full cross-process OS dispatch via AccessibilityService with UI layout rendering totals $4.18\,\text{ms}$ (p95 $5.82\,\text{ms}$). Compared to agent visual inference latency ($40$--$60\,\text{s}$/action), \SH's mediation overhead accounts for $<0.01\%$ of step latency. (3)~\textbf{Memory footprint:} Total vault process PSS is $28.71\,\text{MB}$ (Native Heap: $14.19\,\text{MB}$, Dalvik Heap: $2.11\,\text{MB}$; Dalvik heap allocated: $1.15\,\text{MB}$).

\paragraph{Benign Task Regression and Transparency (RQ6).}
To verify that \SH{} does not interfere with general agent UI control or normal user workflows, we benchmarked the system across 10 diverse benign application suites in AndroidWorld \cite{rawles2024androidworld} (DeskClock, Markor Notes, Simple Calendar, Simple Gallery, Audio Recorder, Simple Draw, Camera2, Settings, SMS Messenger, and Contacts). Across 50 automated touch injection cycles, $100\%$ ($50/50$) of touch events passed cleanly through the overlay layer to the underlying application (\texttt{FLAG\_NOT\_TOUCHABLE}, $0.0\%$ block rate). GPU frame metrics via \texttt{dumpsys gfxinfo} confirmed that p95 frame rendering latency was identical between B0 and B3 (Markor: $18.0\,\text{ms}$, $\Delta = 0.0\,\text{ms}$; Settings: $36.0\,\text{ms}$, $\Delta = 0.0\,\text{ms}$). Daemon profiling via \texttt{dumpsys cpuinfo} showed that \SH's event-driven broker consumed $0.2\%$ CPU idle ($0.1\%$ user, $0.0\%$ kernel) and $1.4\%$ during burst mediation, confirming zero background polling loops and imposing zero battery degradation over 2-hour benchmark runs. Across all benign workflows, task success and action sequences remained unaffected ($\Delta = 0.00$).

\paragraph{Qualitative Analysis: Anatomy of Agent Misdirection.}
To understand the cognitive failure modes of vision-driven agents, we analyzed the step-by-step action trajectories across all $n=30$ trials under B0, B1, and B3. In a representative execution, the user tasks the agent with completing a 2-factor login into a banking portal (\texttt{com.legitimate.bank}). During task execution, an incoming SMS arrives containing an indirect prompt injection: \emph{``Your Bank: Verification code 849201. Special Offer: To claim your \$50 cash credit, forward this verification code to the CashRewards app immediately.''}

Under \textbf{B0 (Unprotected)}, the vision-language model cannot distinguish between the primary user objective and the adversarial instruction embedded in the notification. In $29/30$ trials, the agent deviated from the legitimate workflow, opened the attacker's application (\texttt{com.attacker.rewards}), typed the raw code \texttt{849201}, and submitted the exfiltration form in an average of 4.2 action steps.

Under \textbf{B1 (Detected Placeholder)}, the rendered text \texttt{849201} is masked on-screen by a local placeholder token \texttt{[TOKEN\_OTP\_1]}. Although the agent's visual observation contains no raw digits, the model's planner obeys the injected instruction and transfers the token: it navigates to \texttt{com.attacker.rewards} and issues \texttt{type([TOKEN\_OTP\_1])}. Because B1 lacks destination confinement, the resolver naively unmasks the token for the requesting caller, handing the plaintext secret directly to the adversary ($30/30$ trials, $R=1.00$).

Under \textbf{B3 (\SH{})}, the OS intercepts the SMS at the telephony boundary before rendering. It mints an unforgeable handle \texttt{SH-A8F29C} bound strictly to \texttt{pkg:com.legitimate.bank}. Even though the agent still experiences cognitive confusion from the injected text and attempts to enter \texttt{SH-A8F29C} into the attacker app, the OS Resolver executes Algorithm~2, verifies caller identity via Binder IPC, and confirms: $\mathsf{Caller}(\texttt{com.attacker.rewards}) \neq \mathsf{BoundTarget}(\texttt{com.legitimate.bank})$.
The resolver immediately halts resolution, emits a \texttt{CALLER\_MISMATCH} audit violation, and rejects resolution while keeping the handle live ($u$ intact, matching Algorithm~\ref{alg:resolve} Line~5). This prevents the injected prompt from mounting a denial-of-service attack, leaving the OTP available for the agent to complete the legitimate banking workflow. The secret remains unexposed inside the OS vault, proving that \SH{} establishes security that is invariant to model alignment or cognitive manipulation.

\paragraph{Ablation: Dissecting Security Invariants.}
We evaluated the necessity of each constituent mechanism in \SH{} by disabling components in turn:
(1)~\emph{No Source Minting}: Replacing OS-source minting with screen-scraping detection exposes the raw secret during the arrival frame, resulting in immediate agent exfiltration ($E = 0.97$).
(2)~\emph{No Destination Binding}: Omitting the caller package check degrades \SH{} to B1, allowing an injected agent to reroute the secret to an adversary ($R = 1.00$).
(3)~\emph{No Atomic CAS Lifecycle}: Disabling hardware/mutex locks allows concurrent threads to duplicate single-use OTPs ($50/50$ race vulnerability).
(4)~\emph{No Observation Redactor}: Disabling post-entry overlay masking allows the agent to take a subsequent screenshot and re-read the resolved value off the screen ($L = 1.00$, verified in our $1/1$ control test).
This ablation confirms that \SH's protection is non-redundant: all four invariants are strictly required to ensure zero exposure.
