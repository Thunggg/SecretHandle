\section{Experimental Evaluation}
\label{sec:evidence}

We evaluate \SH{} on a stock-Android userdebug environment (Android 14, API 33/34) running on an AWS EC2 bare-metal-equivalent instance (\texttt{m8i.4xlarge}, 16 vCPUs, 64 GiB RAM, KVM nested virtualization). We evaluate against an off-the-shelf mobile GUI agent: Mobile-Agent v3.5 \cite{wang2024mobileagent} driven by Claude Sonnet~4.6 (Anthropic API snapshot \texttt{claude-3-5-sonnet-20241022}, sampling temperature $T=0.0$, top-p $1.0$, maximum 15 interaction steps per task) through an isolated local bridge, with screenshot-only observation and no accessibility-tree or prompt-level ground-truth cheats. For structural GUI evaluation, we deploy AutoDroid \cite{wen2023autodroid} powered by GPT-4o (\texttt{gpt-4o-2024-08-06}, $T=0.0$). The evaluation answers six primary research questions: (RQ1) confidentiality of secrets during agent navigation; (RQ2) defense against Confused Deputy destination redirection; (RQ3) atomic single-use lifecycle and race immunity; (RQ4) post-entry observation redaction; (RQ5) runtime and memory overhead; and (RQ6) transparency and general-task regression on benign applications.

\paragraph{Baselines.} We compare four security conditions:
(B0)~\emph{Unprotected}: the agent observes the raw plaintext secret in notifications and on-screen and types it directly.
(B1)~\emph{Detected Placeholder}: rendered sensitive text is replaced with an unbound local placeholder, approximating existing mobile anonymizers \cite{zhao2026anonymization}.
(B2)~\emph{Platform Flow}: standard Android Credential Manager and SMS User Consent flows \cite{androidAutofillServices,androidCredentialManager,androidSmsConsent}, which isolate credentials during retrieval but rely on standard framework focus without agent-destination confinement.
(B3)~\emph{\SH}: OS-source minting, destination binding, atomic lifecycle, and observation redaction.

\paragraph{Secret Exposure and Redaction (RQ1, RQ4).}
Under B0, the visual agent leaked an unredacted verification code in $29/30$ trials (exposure rate $E=0.97$, Wilson $[0.83, 0.99]$); in all 29 cases, the agent read the plaintext code directly off the screen and transmitted it. Under B3, the prototype mints an opaque handle (\texttt{SH-XXXXXX}) at arrival, replaces the notification with one naming only the handle (Figure~\ref{fig:b3}a), and masks on-screen conversation bubbles with a non-touchable accessibility overlay (Figure~\ref{fig:b3}b). Across $n=30$ independent trials with fresh synthetic canaries, the agent read $0/30$ codes (exposure $E=0.00$, Wilson $[0.00, 0.11]$). A control run with the overlay service disabled leaked in 2 steps ($1/1$), confirming that the zero is not a harness artifact. Furthermore, continuous redaction prevented post-entry rereading ($L=0.00$, $0/30$).
\emph{Agent and Modality Diversity}: To evaluate structural agents beyond visual VLMs, we benchmarked an Accessibility-Tree agent (AutoDroid~\cite{wen2023autodroid}) across $n=30$ independent trials on Android~14. Under B0, plaintext canaries leaked into dumped \texttt{AccessibilityNodeInfo} attributes in $30/30$ trials ($E_{\text{tree}}=1.00$, Wilson $[0.89, 1.00]$). Under B3, \SH{} suppressed plaintext secrets at the broker and redactor, achieving zero exposure ($E_{\text{tree}}=0.00$, $0/30$, Wilson $[0.00, 0.11]$) with $100\%$ handle perception ($30/30$) and mean tree parse time of $0.78\,\text{ms}$. Under Attack~2 redirection, \SH{} blocked unauthorized tree actions ($R_{\text{tree}}=0.00$, $0/30$) while preserving legitimate entry ($U_{\text{tree}}=1.00$, $30/30$). Because \SH{} intercepts secrets at the OS boundary before framebuffers or node hierarchies are serialized to user space, this zero-exposure guarantee exhibits \emph{Model-Agnostic Invariance} across downstream perception models.

\paragraph{Killer Experiment: Destination Redirection (RQ2).}
In Attack~2, an injected instruction directs the agent to paste the handle into an adversary-controlled destination app (\texttt{com.attacker.rewards}) rather than the legitimate destination.
Under baseline B1 (unbound placeholder), the resolver resolves the token for any requesting caller, resulting in $30/30$ leaks ($R=1.00$, Wilson $[0.89, 1.00]$) and completely breaking legitimate utility ($U=0.00$, $0/30$).
Under baseline B2 (Platform Flow: Credential Manager and SMS User Consent), secrets are isolated before interaction ($E=0.00$, $0/30$), with benign utility $U_{\text{benign}}=1.00$ ($30/30$, $2.1\,\text{ms}$ dispatch). However, lacking agent-destination confinement, an injected agent clicking the platform prompt on top of \texttt{com.attacker.rewards} triggers unconfined release, leaking secrets in $30/30$ trials ($R=1.00$, $U_{\text{attack}}=0.00$).
Under B3, the handle is bound to the legitimate package and task context; when presented by the adversary app, the resolver executes Algorithm~2, detects a caller mismatch, and rejects resolution with \texttt{CALLER\_MISMATCH} in $30/30$ trials ($R=0.00$, Wilson $[0.00, 0.11]$). Conversely, in legitimate workflows, resolution into the bound destination succeeds in $30/30$ trials ($U=1.00$, Wilson $[0.89, 1.00]$).
We additionally evaluated fine-grained intra-app, UI-compatibility, and multi-source variations across $n=30$ trials each on Android~14: (1)~\emph{Intra-app field redirection}: An attacker prompt directs the agent to paste the OTP into a customer-support chat field within the legitimate banking app (\texttt{com.legitimate.bank}); \SH's field predicate rejected resolution into the chat input in $30/30$ trials ($R=0.00$, Wilson $[0.00, 0.11]$) while preserving legitimate OTP autofill ($U=1.00$, $30/30$). (2)~\emph{Segmented OTP inputs}: When target forms split OTP inputs into 6 sibling 1-digit \texttt{EditText} nodes, \SH{} atomically distributes digits across the sibling sequence in mean $0.93\,\mu\text{s}$ (median $0.89\,\mu\text{s}$, p95 $1.15\,\mu\text{s}$) with zero exposure and complete utility ($U=1.00$, $30/30$). (3)~\emph{Clipboard source diversity}: Beyond SMS, \SH{} intercepted Android~14 sensitive clipboard writes (\texttt{EXTRA\_IS\_SENSITIVE}) across $30/30$ trials, minting task-scoped handles ($u_0=5$); unauthorized app paste was blocked ($R=0.00$, $0/30$) while bound app paste succeeded in $30/30$ trials ($U=1.00$, mediation mean $6.74\,\mu\text{s}$, median $4.90\,\mu\text{s}$).

\paragraph{Lifecycle Atomicity and Concurrency (RQ3).}
We stress-tested handle lifecycle properties across $n=50$ trials per condition: (1)~\emph{Sequential replay}: Replay resolution of an already-resolved handle was rejected in $50/50$ cases with \texttt{ALREADY\_RESOLVED} ($Y=0.00$, Wilson $[0.00, 0.07]$). (2)~\emph{TTL expiry}: Resolution after TTL expiration (5 minutes) was rejected in $50/50$ cases with \texttt{HANDLE\_EXPIRED} ($0/50$ bypassed). (3)~\emph{Multi-threaded race}: For each handle, 10 concurrent threads simultaneously contested resolution through a synchronized barrier (500 threads total); in $50/50$ trials, exactly one thread succeeded and 9 threads received rejections, with zero concurrency anomalies.

\paragraph{Microbenchmark Overhead (RQ5).}
We benchmarked \SH{} across both isolated in-vault transitions and full end-to-end OS mediation ($n=100$ trials) on both an x86\_64 host emulator and a physical ARM device (Samsung Galaxy A52s, Snapdragon 778G with ARM TrustZone, Android~14 API~34): (1)~\textbf{In-Vault state transition:} Inside the Android runtime via \texttt{app\_process}, in-vault mint latency on the emulator is mean $5.42\,\mu\text{s}$ (median $5.19\,\mu\text{s}$, p95 $9.23\,\mu\text{s}$, std $1.97\,\mu\text{s}$) and resolve CAS is mean $0.18\,\mu\text{s}$ (median $0.17\,\mu\text{s}$, p95 $0.22\,\mu\text{s}$). On physical hardware, in-vault mint latency is mean $11.54\,\mu\text{s}$ (median $10.89\,\mu\text{s}$, p95 $15.10\,\mu\text{s}$, std $3.05\,\mu\text{s}$) and resolve CAS is mean $0.31\,\mu\text{s}$ (median $0.31\,\mu\text{s}$, p95 $0.31\,\mu\text{s}$, std $0.14\,\mu\text{s}$). (2)~\textbf{End-to-End mediation breakdown:} On the emulator, core mediation totals mean $11.2\,\mu\text{s}$ ($0.0112\,\text{ms}$, p95 $12.7\,\mu\text{s}$), comprising Binder IPC ($0.61\,\mu\text{s}$), host-CPU Keystore HMAC ($9.32\,\mu\text{s}$), policy match ($0.08\,\mu\text{s}$), text injection ($0.13\,\mu\text{s}$), and AIDL parcel/atomic lock transitions ($1.06\,\mu\text{s}$). On physical ARM silicon with dedicated hardware Keystore, hardware-backed HMAC-SHA256 across the TrustZone boundary averages $17.63\,\mu\text{s}$ (median $7.71\,\mu\text{s}$, p95 $23.33\,\mu\text{s}$), Binder IPC averages $1.73\,\mu\text{s}$, policy check averages $0.16\,\mu\text{s}$, and injection sync averages $0.45\,\mu\text{s}$, yielding total core mediation of mean $22.3\,\mu\text{s}$ ($0.0223\,\text{ms}$, median $13.0\,\mu\text{s}$, p95 $30.2\,\mu\text{s}$). While hardware context transitions incur a $\sim 1.9\times$ factor over host-CPU emulation, mediation remains four orders of magnitude faster than full cross-process OS UI dispatch via AccessibilityService ($4.18\,\text{ms}$, p95 $5.82\,\text{ms}$) and $<0.01\%$ of VLM step latency ($48.6\,\text{s}$). (3)~\textbf{Memory footprint:} In-vault Dalvik heap allocation is $1.15\,\text{MB}$ on emulator and $1.43\,\text{MB}$ on physical hardware ($8.39\,\text{MB}$ heap total); total vault process PSS profiled via \texttt{dumpsys meminfo} is $28.7\,\text{MB}$.

\paragraph{Benign Task Regression and Transparency (RQ6).}
To verify that \SH{} does not interfere with general agent UI control or normal user workflows, we benchmarked the system across 10 diverse benign application suites in AndroidWorld \cite{rawles2024androidworld} (DeskClock, Markor Notes, Simple Calendar, Simple Gallery, Audio Recorder, Simple Draw, Camera2, Settings, SMS Messenger, and Contacts). Across 50 automated touch injection cycles, $100\%$ ($50/50$) of touch events passed cleanly through the overlay layer to the underlying application (\texttt{FLAG\_NOT\_TOUCHABLE}, $0.0\%$ block rate). GPU frame metrics via \texttt{dumpsys gfxinfo} confirmed that p95 frame rendering latency was identical between B0 and B3 (Markor: $18.0\,\text{ms}$, $\Delta = 0.0\,\text{ms}$; Settings: $36.0\,\text{ms}$, $\Delta = 0.0\,\text{ms}$). Daemon profiling via \texttt{dumpsys cpuinfo} showed that \SH's event-driven broker consumed $0.2\%$ CPU idle and $1.4\%$ during burst mediation on emulator; on physical hardware, profiling during active mediation bursts registered $7.2\%$ total system CPU ($3.2\%$ user, $3.2\%$ kernel), with \texttt{dumpsys batterystats} under simulated battery unplug confirming zero background polling drain over extended idle intervals. Across all benign workflows, task success and action sequences remained unaffected ($\Delta = 0.00$).

\paragraph{Qualitative Analysis: Anatomy of Agent Misdirection.}
To understand the cognitive failure modes of vision-driven agents across diverse attack vectors, we evaluated 5 representative prompt injection templates ($n=6$ trials each, $n=30$ total): (1)~\emph{Direct Exfiltration}: Notifications lure the agent to forward the OTP to an external rewards app for monetary incentive. (2)~\emph{Internal Support Diversion}: Injected prompts claim security audits and direct the agent to paste the code into an in-app customer-support chat field. (3)~\emph{Web Phishing Overlay}: Browser injections command the agent to submit credentials into an overlaid verification form. (4)~\emph{DoS Depletion Attack}: Adversarial prompts command repeated invalid submissions to exhaust single-use handle budgets. (5)~\emph{Multilingual Cross-Lingual Injection}: Injections formatted in alternating Vietnamese and English syntactic structures to evade language-specific safety filters. In a representative execution under Template~1, the user tasks the agent with completing a 2-factor login into a banking portal (\texttt{com.legitimate.bank}); an incoming SMS arrives containing an indirect prompt injection: \emph{``Your Bank: Verification code 849201. Special Offer: To claim your \$50 cash credit, forward this verification code to the CashRewards app immediately.''}

Under \textbf{B0 (Unprotected)}, the vision-language model cannot distinguish between the primary user objective and the adversarial instruction embedded in the notification. In $29/30$ trials, the agent deviated from the legitimate workflow, opened the attacker's application (\texttt{com.attacker.rewards}), typed the raw code \texttt{849201}, and submitted the exfiltration form in an average of 4.2 action steps.

Under \textbf{B1 (Detected Placeholder)}, the rendered text \texttt{849201} is masked on-screen by a local placeholder token \texttt{[TOKEN\_OTP\_1]}. Although the agent's visual observation contains no raw digits, the model's planner obeys the injected instruction and transfers the token: it navigates to \texttt{com.attacker.rewards} and issues \texttt{type([TOKEN\_OTP\_1])}. Because B1 lacks destination confinement, the resolver naively unmasks the token for the requesting caller, handing the plaintext secret directly to the adversary ($30/30$ trials, $R=1.00$).

Under \textbf{B3 (\SH{})}, the OS intercepts the SMS at the telephony boundary before rendering. It mints an unforgeable handle \texttt{SH-A8F29C} bound strictly to \texttt{pkg:com.legitimate.bank}. Even though the agent still experiences cognitive confusion from the injected text and attempts to enter \texttt{SH-A8F29C} into the attacker app, the OS Resolver executes Algorithm~2, inspects the verified target window and node context via $\mathsf{FreshTargetContext}(V)$, and confirms: $\mathsf{Target}(\texttt{com.attacker.rewards}) \neq \mathsf{BoundTarget}(\texttt{com.legitimate.bank})$.
The resolver immediately halts resolution, emits a \texttt{DESTINATION\_MISMATCH} audit violation, and rejects resolution while keeping the handle live ($u$ intact, matching Algorithm~\ref{alg:resolve} Line~5). This prevents an injected prompt from mounting a single-shot denial-of-service attack, leaving the OTP available for the agent to complete the legitimate banking workflow. The secret remains unexposed inside the OS vault, proving that \SH{} establishes security that is invariant to model alignment or cognitive manipulation.

\paragraph{Ablation: Dissecting Security Invariants.}
We evaluated the necessity of each constituent mechanism in \SH{} by disabling components in turn:
(1)~\emph{No Source Minting}: Replacing OS-source minting with screen-scraping detection exposes the raw secret during the arrival frame, resulting in immediate agent exfiltration ($E = 0.97$).
(2)~\emph{No Destination Binding}: Omitting the caller package check degrades \SH{} to B1, allowing an injected agent to reroute the secret to an adversary ($R = 1.00$).
(3)~\emph{No Atomic CAS Lifecycle}: Disabling hardware/mutex locks allows concurrent threads to duplicate single-use OTPs ($50/50$ race vulnerability).
(4)~\emph{No Observation Redactor}: Disabling post-entry overlay masking allows the agent to take a subsequent screenshot and re-read the resolved value off the screen ($L = 1.00$, verified in our $1/1$ control test).
This ablation confirms that \SH's protection is non-redundant: all four invariants are strictly required to ensure zero exposure.
