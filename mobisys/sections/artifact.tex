\section{Artifact Appendix}
\label{sec:artifact}

\paragraph{Scope.} The \SH{} artifact repository (\url{https://github.com/SecretHandle/SecretHandle}, Apache License~2.0) ships four directories evaluated in Section~\ref{sec:evidence}: (1)~\texttt{SecretHandle/}: Python reference model (\texttt{src/secrethandle}), offline property verifier, and \texttt{pytest} suite; (2)~\texttt{device/\allowbreak b3-secrethandle/}: Android~14 prototype APK (\texttt{b3secrethandle.apk}) and \texttt{BenchmarkRunner}; (3)~\texttt{device/\allowbreak b0-otp-forwarding/}: B0 exfiltration harness; and (4)~\texttt{tools/} and \texttt{output/}: real-app UI compatibility auditor and archived empirical JSON logs.

\paragraph{Contents.}
(i)~\texttt{SecretHandle/src}: Python state-machine model, policy solvers, offline tests, and synthetic-canary verifier;
(ii)~\texttt{device/\allowbreak b3-\allowbreak secrethandle}: Java source for \texttt{Vault}, \texttt{Secret\allowbreak Broker\allowbreak Service} (\texttt{Notification\allowbreak Listener\allowbreak Service}), \texttt{Redaction\allowbreak Accessibility\allowbreak Service} (\texttt{TYPE\_\allowbreak ACCESSIBILITY\_\allowbreak OVERLAY}), \texttt{MainActivity}, and \texttt{Benchmark\allowbreak Runner.java};
(iii)~\texttt{tools/} and \texttt{run\_\allowbreak tier4\_\allowbreak physical\_\allowbreak benchmark.ps1}: physical-device runner, \texttt{audit\_\allowbreak real\_\allowbreak apps\_\allowbreak compatibility.py}, and \texttt{manuscript\_\allowbreak check.py};
(iv)~\texttt{output/}: archived datasets (\texttt{physical\_\allowbreak device\_\allowbreak benchmark.json}, \texttt{benchmark\_\allowbreak overhead\_\allowbreak lifecycle\_\allowbreak redirection.json}, \texttt{rq6\_\allowbreak benign\_\allowbreak regression\_\allowbreak results.json}, \texttt{real\_\allowbreak apps\_\allowbreak compatibility\_\allowbreak audit.json}, etc.).

\paragraph{One-command offline verification.} Inside \texttt{SecretHandle/} (Python 3.10+):
\begin{small}
\begin{verbatim}
cd SecretHandle && python -m venv .venv
source .venv/bin/activate && pip install -e '.[dev]'
make check
\end{verbatim}
\end{small}
\texttt{make check} runs \texttt{ruff}, \texttt{mypy}, \texttt{pytest}, and \texttt{scripts/\allowbreak smoke\_\allowbreak check.py} over 6,400 synthetic runs (seed \texttt{20261017}) with zero leak anomalies.

\paragraph{On-device Android 14 experiment reproduction.} To install the Android~14 prototype, execute \texttt{BenchmarkRunner}, and audit UI compatibility:
\begin{small}
\begin{verbatim}
# 1. Verify SELinux & install/enable prototype
adb unroot && adb shell getenforce
APK=device/b3-secrethandle/build/b3secrethandle.apk
adb install -r $APK
adb shell cmd notification allow_listener \
  com.secrethandle.b3/.SecretBrokerService
adb shell settings put secure \
  enabled_accessibility_services \
  com.secrethandle.b3/.RedactionAccessibilityService
adb shell settings put secure accessibility_enabled 1
# 2. Run on-device microbenchmarks (or audit UI)
adb push $APK /data/local/tmp/bench.jar
adb shell CLASSPATH=/data/local/tmp/bench.jar \
  app_process /data/local/tmp \
  com.secrethandle.b3.BenchmarkRunner all
python tools/audit_real_apps_compatibility.py \
  --capture "AppName" --category "Fintech"
\end{verbatim}
\end{small}
All benchmarks use synthetic canary secrets or static UI tree dumps without storing user text; aggregated metrics from external KVM agent runs (\texttt{Mobile-Agent v3.5}, \texttt{AutoDroid}) and physical-device captures reside in \texttt{output/*.json}.

\paragraph{Integrity and license.} Offline checks log seeds and digests in \texttt{provenance.json}. Source code, harnesses, auditors, and archived JSON logs are released under Apache~2.0.

\paragraph{Adversarial delivery channels.} Injection payloads were introduced via two realistic vectors: (1)~unredacted non-banking notifications (e.g., promotional messages from external applications), and (2)~untrusted third-party content (e.g., chat logs or web pages). Under B0, all 5 templates successfully diverted the visual agent ($29/30$ exfiltration rate). Under \SH{} (B3), the OS reference monitor enforced destination verification, blocking all redirection and exfiltration attempts ($0/30$ exposure, $0/30$ redirection).
