\section{Design: Usable but Invisible Secrets}
\label{sec:design}

A \emph{secret handle} is an unforgeable capability object minted by the OS at the authoritative source. While prior user-space text anonymizers seek to make sensitive strings ``available but invisible'' through local text placeholders \cite{zhao2026anonymization}, \SH{} introduces an OS-enforced capability architecture where a handle carries (i) a secret \emph{type}, (ii) a \emph{destination binding}---an allowed package and, for web, a document origin, plus an allowed field class---derived from the task and, where available, from the source's own binding (e.g., the app hash used by the SMS Retriever \cite{androidSmsRetriever}), and (iii) a \emph{lifecycle}: single-use with a TTL for OTPs, task-scoped for identifiers, and confirm-per-use for payment. The agent observes only the handle and reasons about it (``the code arrived; enter it into the login field''); it never observes the value.

\paragraph{Architecture.} Four components sit inside the OS:
\begin{itemize}[leftmargin=*]
  \item \textbf{Handle mint} (new system service): hooks the OTP pipeline, Credential Manager, clipboard, and wallet to mint typed, bound, unforgeable handles; keys live in hardware-backed storage.
  \item \textbf{Resolver} (input-dispatch / accessibility action path): on \Enter(handle), authenticates the handle, checks the target node's package/origin/field class against the binding, injects the value, and enforces use count and TTL under a reservation lock.
  \item \textbf{Observation redactor} (accessibility service and the agent's screenshot path): masks resolved values in the agent's view.
  \item \textbf{Agent SDK}: surfaces handles in the observation, provides the \Enter(handle) action, and adapts open-source agents.
\end{itemize}

\paragraph{Representing handles to agents.} A handle must be usable without resembling a plausible raw secret. The accessibility tree exposes role \texttt{secret\_handle}, a stable ID, type, coarse destination, and expiry bucket; the screenshot shows an icon and short label (``OTP ready for SecureBank -- 38s'') without secret length or digits. The SDK adds \Enter(handleId, targetNodeToken). For vision-only agents using coordinates $(x,y)$, the SDK bridge intercepts $\mathsf{Type}(\text{``\texttt{SH-XXXXXX}''}, (x,y))$ before IME dispatch, resolves the node at $(x,y)$, and invokes \Enter{} internally without exposing the handle string to the target buffer prior to authorization. Spoofed pixels or labels cannot pass cryptographic verification, and framework-owned overlay extras harden the indicator surface.

\paragraph{Resolution as the enforcement point.} Security hinges on resolution: injection proceeds only after handle authentication and target validation. Prompts targeting an attacker package, foreign origin, unbound field, or stale node fail closed under a reservation lock, and post-entry redaction masks the field from subsequent frames.

\paragraph{Policy language.} A destination predicate specifies four attribute sets---package, document origin, field class, and target node---each with a \emph{require} flag (missing required attributes fail closed). Handle policy intersects three constraints: task policy $D_T$ (derived from the user-launched foreground package, independent of the untrusted planner), source policy $D_S$ (e.g., SMS Retriever's 11-character app hash~\cite{androidSmsRetriever} or Digital Asset Links~\cite{androidCredentialManager}; wildcard $*$ for generic SMS), and type policy (e.g., OTP autofill hints). Intersection only narrows destinations, yielding an auditable policy algebra without detector dependence.

\paragraph{Lifecycle and reservation.} Records transition across \textsc{live}, \textsc{reserved}, \textsc{consumed}, and terminal \textsc{expired}/\textsc{revoked} states. Reservation decrements the use budget atomically \emph{before} delivery to block concurrent replay; single-use handles whose delivery outcome is uncertain are consumed conservatively. OTPs carry short TTLs and budget $1$; identifiers are task-scoped; payment handles require per-use confirmation. Task end, screen lock, profile switch, or package change revokes stale handles.

\paragraph{Redaction and observation closure.} Because resolved text reappears in subsequent frames, the redactor registers an obligation before delivery and masks the target's accessibility value, text-change events, and screenshot bounds for the agent principal alone (the app and user retain normal visibility). Obligations follow a stable view/window token (masking the containing window if tracking fails), and the SDK bridge synchronizes screenshot captures with \texttt{SurfaceFlinger} overlay commits to close scroll/arrival races until field clear, window close, or task end.

\paragraph{Concurrency and time-of-check/time-of-use.} Three races are bounded: (1)~concurrent resolve calls serialize via atomic reservation (Prop.~\ref{prop:singleuse}); (2)~resolver re-validates target context immediately before commit under a one-shot binding; and (3)~pre-delivery obligation registration ensures captures never observe unmasked text. Changed target generations abort fail-closed.

\paragraph{Auditing without secret leakage.} Each audit entry logs event type, per-install pseudonymous handle ID, type, source/destination classes, decision, coarse latency, and policy version, omitting raw secrets, app text, full URLs, and authenticators.

\paragraph{Building blocks and deployment modes.} Destination binding reuses Android package identity and WebView origin; unforgeability uses HMAC~\cite{rfc2104} over canonical metadata with key separation. Upstream AOSP integrates into \texttt{system\_server}, \texttt{InputDispatcher}, and \texttt{ViewRootImpl}, whereas our stock Android~14 prototype realizes these policies via a user-granted broker APK isolated from the agent UID (\S\ref{sec:algorithm}, Table~\ref{tab:aosp_vs_stock}; Fig.~\ref{fig:architecture}).
