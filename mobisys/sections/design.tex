\section{Design: Usable but Invisible Secrets}
\label{sec:design}

A \emph{secret handle} is an unforgeable capability object minted by the OS at the authoritative source. It carries (i) a secret \emph{type}, (ii) a \emph{destination binding}---an allowed package and, for web, a document origin, plus an allowed field class---derived from the task and, where available, from the source's own binding (e.g., the app hash used by the SMS Retriever \cite{androidSmsRetriever}), and (iii) a \emph{lifecycle}: single-use with a TTL for OTPs, task-scoped for identifiers, and confirm-per-use for payment. The agent observes only the handle and reasons about it (``the code arrived; enter it into the login field''); it never observes the value.

\paragraph{Architecture.} Four components sit inside the OS:
\begin{itemize}[leftmargin=*]
  \item \textbf{Handle mint} (new system service): hooks the OTP pipeline, Credential Manager, clipboard, and wallet to mint typed, bound, unforgeable handles; keys live in hardware-backed storage.
  \item \textbf{Resolver} (input-dispatch / accessibility action path): on \Enter(handle), authenticates the handle, checks the target node's package/origin/field class against the binding, injects the value, and enforces use count and TTL under a reservation lock.
  \item \textbf{Observation redactor} (accessibility service and the agent's screenshot path): masks resolved values in the agent's view.
  \item \textbf{Agent SDK}: surfaces handles in the observation, provides the \Enter(handle) action, and adapts open-source agents.
\end{itemize}

\paragraph{Representing handles to agents.} A handle must be usable without resembling a plausible raw secret. The accessibility tree exposes a role such as \texttt{secret\_handle}, a stable handle ID, the type, a permitted coarse destination, and an expiry bucket; the screenshot shows an icon and a short label such as ``OTP ready for SecureBank -- 38s'' and never renders the code length or digits. The SDK adds \Enter(handleId, targetNodeToken) to the action schema. A malicious app can draw identical pixels or set a similar accessibility label, but it cannot cause resolution: the visible string alone lacks a valid authenticated record, and the system overlays handles in a reserved, framework-owned surface marked with an extra that ordinary apps cannot set. This is usability hardening; cryptographic acceptance, not rendering, remains the security boundary.

\paragraph{Resolution as the enforcement point.} The security hinges on resolution: a value is injected only if the handle authenticates and the target is inside the binding. An injected instruction that targets an attacker package, a foreign origin, a non-bound field, or a stale/recycled node is rejected, regardless of how convincingly the agent was manipulated. A booking of one use under a lock makes replay and concurrent double-resolution fail. After injection, the redactor prevents the value from reappearing in the next accessibility tree or screenshot.

\paragraph{Policy language.} A handle's destination predicate is a finite record over four attribute sets---package, document origin, field class, and target node---each with a \emph{require} flag. An attribute that is required but absent at the target fails closed. A minted handle's policy is the intersection of three policies: the task policy (which packages the task authorizes), the source policy (what the authoritative source can bind, such as an SMS Retriever app hash), and the type policy (e.g., an OTP must land in a field classified as an OTP field). Intersection is monotone and can only shrink the allowed destination, so a compromise anywhere in the chain cannot broaden where a value may go. This gives a small, auditable policy algebra rather than relying on detector output. Weak evidence such as app-declared autofill hints or labels may supplement, but never replace, trusted framework signals.

\paragraph{Lifecycle and reservation.} A record moves through \textsc{live}, \textsc{reserved}, \textsc{consumed}, and the terminal \textsc{expired}/\textsc{revoked} states. Resolution reserves the record under an atomic transition that decrements the use budget \emph{at reservation time} (not at delivery), so a concurrent or crashed attempt cannot be replayed into a second delivery; a reservation whose delivery is uncertain is consumed conservatively for single-use types. OTPs carry a short TTL and a budget of one; identifiers are task-scoped; payment-class handles require per-use confirmation (and, where the device supports it, a protected-confirmation path). Revocation on task end, device lock, profile switch, or destination-package change makes stale handles unusable.

\paragraph{Redaction and observation closure.} Injection alone is insufficient, because the entered value reappears in the next frame. The redactor registers an obligation before delivery and, at capture time, replaces the target's accessibility value, text-change events, and screenshot region with a typed mask for the agent principal only; the app and the user still see the real value. Because bounds can move between injection and capture, each obligation follows a stable view/window token and recomputes bounds when the frame is serialized; if the view cannot be re-identified, policy masks the containing window. Redaction ends when the field clears, the window closes, the task ends, or trusted app state proves the value is gone. A timer alone is insufficient, because a slow agent could observe the value just after it fires; conversely, indefinite redaction could hide unrelated user content in a recycled view, so obligations are bound to a content generation or an explicit clearing event.

\paragraph{Concurrency and time-of-check/time-of-use.} Three races matter. First, two agent calls may attempt the same handle; atomic reservation (Proposition~\ref{prop:singleuse}) lets exactly one win. Second, the target may change after it is checked; the resolver re-derives the target context immediately before injection and binds a one-shot injection capability to the reservation, narrowing the window. Third, capture may race with entry; registering the redaction obligation \emph{before} delivery guarantees that any screenshot or accessibility read observes an active obligation whenever the field can hold the value. The design favors fail-closed behavior: a changed target generation is not followed automatically, and an unknown delivery outcome consumes a one-use handle.

\paragraph{Auditing without secret leakage.} The audit record contains the event type, a pseudonymous handle ID, the type, source and destination classes, the decision, a coarse latency, and the policy version. It excludes raw values, application text, screenshots, full origins containing user identifiers, and authenticators. Per-install keyed pseudonyms allow joins within an experiment without becoming globally linkable, giving an observable deployment trail that does not itself become a disclosure channel.

\paragraph{Building blocks and deployment modes.} Destination binding reuses Android package identity and WebView origin; unforgeability uses a message authenticator \cite{rfc2104} over a canonical encoding of the handle fields with a key separated from the value; lifecycle and reservation are ordinary OS state transitions. The strongest deployment modifies AOSP across sources, accessibility, screenshot composition, and input dispatch; an OEM extension can add wallet and hardware-key integration; a research prototype may begin with SMS, a purpose-built credential provider, and open test apps. A user-space accessibility-service prototype can demonstrate workflows but cannot establish the same guarantee, because it receives observations after framework serialization and may have to type through an agent-visible path; results from that mode are feasibility measurements, not validation of the reference-monitor assumptions. The main engineering is wiring the mint points and the resolver into the input path, and the design composes with blind-actuation approaches in which the agent acts on a node it cannot read.
