Table~\ref{tab:comparison} summarizes the structural differences across contemporary secret-handling and agent-isolation paradigms. While existing defenses tackle individual aspects of the problem---such as post-hoc taint tracking, heuristic prompt rewriting, or planner-level tool mediation---none simultaneously guarantee zero plaintext observation and destination-bound resolution for vision-driven GUI agents.

\paragraph{Placeholder and anonymization defenses.} Mobile placeholder schemes replace sensitive rendered text with a type-preserving token and reverse the mapping at use time \cite{zhao2026anonymization}; the closest recent work resolves a \texttt{type(PLACEHOLDER)} locally but is detector-based, session-scoped, and validates index ranges rather than which field receives a resolved value. We differ fundamentally on mint source (authoritative OS source, not screen scraping), unforgeability, destination-and-task binding, typed lifecycle, and a threat model that includes redirection. As our empirical evaluation in Section~\ref{sec:evidence} demonstrates, unbound placeholder mechanisms remain completely vulnerable to Confused Deputy redirection ($30/30$ leakage under Attack~2), whereas \SH{} prevents redirection at the OS boundary.

\paragraph{Capability and isolation approaches.} Planner-side capability schemes and dual-model patterns hide values from the planner in tool-calling settings \cite{debenedetti2025camel,costa2025fides}; isolation and privilege-minimization designs restrict what a tool agent may do \cite{bagdasarian2024airgap,wu2025isolategpt,shi2025progent}. These operate in the planning or tool layer rather than at the point where a secret crosses from an OS source into a UI field. They assume structured API interfaces and cannot protect arbitrary graphical mobile environments where untrusted vision agents observe raw pixels and actuate via accessibility events.

\paragraph{Prompt sanitizers.} Detection-and-rewrite approaches suppress or restore sensitive spans in prompts \cite{siyan2025papillon,zeng2025privacyrestore,chong2024casper}. They reduce model-side exposure but do not bind a resolved value to a destination and are not OS-enforced. Furthermore, prompt sanitization is probabilistic: adversarial formatting, obfuscation, or multilingual prompt injection can reliably evade detection filters.

\paragraph{Platform and industry mechanisms.} The SMS Retriever and User Consent APIs \cite{androidSmsRetriever,androidSmsConsent}, sensitive-notification OTP pipeline \cite{android15privacy}, Credential Manager \cite{androidCredentialManager}, autofill \cite{androidAutofill,androidAutofillServices}, clipboard sensitivity flag \cite{androidClipboard}, and Protected Confirmation \cite{androidProtectedConfirmation} are valuable building blocks, but autofill and Credential Manager are app-initiated and trust the app. \SH{} composes them with OS-level destination binding and lifecycle enforcement.

\paragraph{OS mechanisms and reference monitors.} \SH{} applies complete mediation and least privilege \cite{saltzer1975protection} to secrets typed into a UI by an untrusted process. Capability systems like Capsicum confine authority to scoped handles \cite{watson2010capsicum}, and Android mediates isolation through install-time and runtime models \cite{felt2011permission,bugiel2013flexible,rossi2021seapp}. UI confidentiality systems such as SchrodinText \cite{continella2020schrodintext} isolate sensitive display text, while Rushmore \cite{andrus2015rushmore} and GYRUS \cite{jang2014gyrus} enforce trusted display paths and intent validation. Conversely, Cloak \& Dagger \cite{fratantonio2017cloak} revealed accessibility overlay abuses; \SH{} leverages OS-enforced, non-touchable overlays in the reverse direction to shield authoritative secrets from untrusted vision agents. Taint systems track sensitive data flows post-hoc \cite{enck2010taintdroid,yan2012droidscope}, whereas \SH{} prevents values from entering agent perception entirely. Dennis and Van Horn founded the capability concept \cite{dennis1966semantics}; our contribution is the destination-and-task predicate over package, origin, and field class with an authenticated, lifecycle-bounded handle.

\paragraph{Credential and token standards.} OTP construction and validation are standardized by HOTP and TOTP \cite{rfc4226,rfc6238}, and token binding schemes constrain where an OAuth-bound token may be replayed \cite{rfc8707,rfc9449,rfc9700}. WebAuthn and passkeys remove a shared secret from the flow entirely \cite{webauthn3,nist80063b}. These authenticate a credential, a user, or a server endpoint, but they do not decide which on-device UI field may receive a captured value; \SH{} complements them by constraining the resolution sink inside the OS. Finally, documented agent OTP exfiltration and environmental prompt injection directly motivate our threat model \cite{du2025mobileattacks,liao2024eia,chen2025fineprint,greshake2023indirect,debenedetti2024agentdojo,zhan2024injecagent}.
