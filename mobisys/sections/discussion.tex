\section{Discussion and Limitations}
\label{sec:discussion}

\subsection{Deployment Roadmap and Systems Considerations}

\paragraph{Path to Google AOSP Upstream.}
While evaluated via an Accessibility Service and Notification Broker on stock Android images, \SH's architecture (Section~\ref{sec:design}) targets direct upstream integration into Android's \texttt{system\_server} via three enhancements: (1)~\textbf{Input Dispatch Integration:} Rather than utilizing accessibility overlay masking, the \texttt{Resolver} hooks directly into Android's \texttt{InputDispatcher} and \texttt{ViewRootImpl}. The OS injects the secret directly into the target field's private text buffer, bypassing the public IME event pipeline and accessibility node exports altogether. (2)~\textbf{Hardware-Backed Root of Trust:} The handle authenticator key is provisioned inside Android's Hardware Keystore (backed by ARM TrustZone or a StrongBox keymaster), guaranteeing that handle MACs cannot be forged even under root compromise. (3)~\textbf{Unified System Service:} Mint points and the Vault are consolidated into a first-class \texttt{SecretHandleManagerService} exposed via AIDL and isolated via SELinux.

\paragraph{Memory Hygiene, Fraud Coexistence, and Model Generality.}
To defend against memory scraping, Vault secrets are pinned to non-swappable native pages (\texttt{mlock()}) and zeroed upon resolution or expiry (\texttt{explicit\_bzero}). Contextual listeners discard handles on screen lock (\texttt{ACTION\_SCREEN\_OFF}), backgrounding, or profile switches. For apps with anti-bot SDKs, the resolver optionally issues an authenticated receipt (\texttt{AttestedResolutionReceipt}). Operating at the OS boundary, \SH's guarantees hold across commercial VLMs (Claude, GPT-4o), open-weight models (Qwen-VL), and tree planners.

\paragraph{Ethics, Reproducibility, and Transparency.}
All experiments exclusively utilize synthetic canaries, isolated loopback endpoints, and open benchmark applications; no human subjects or production credentials were used. Complete experiment runners, configuration seeds, and provenance logs are open-sourced under Apache 2.0 (Appendix~\ref{sec:artifact}). Portions of the manuscript were drafted with LLM assistance; all technical claims, formal proofs, and measurements were produced and verified by the authors.

\subsection{Limitations and Threats to Validity}
\label{sec:limitations}

\paragraph{Platform Scope and Operating System Trust.}
Our empirical results validate \SH{} on Android~14 via an SMS broker, accessibility overlay masking, and vault resolver, confirming capability invariants on stock emulators. Production deployments require in-tree \texttt{system\_server} dispatch, hardware-keystore isolation, and AOSP integration. Our model trusts the kernel and system server: a compromised kernel can forge identities or bypass redaction. Hardware keystores prevent key exfiltration but cannot enforce policy if the framework is compromised. Unmonitored platform channels (e.g., crash dumps or OEM screen readers) remain out of scope.

\paragraph{Web Views and Origin Binding.}
Package identity is insufficient for origin-level confinement in browser contexts. Enforcing destination binding between an input field, frame, and authenticated document origin requires deeper Chromium and WebView framework attestation. Under complex redirects, cross-origin iframes, or custom tabs, \SH's safe fallback is fail-closed rejection or explicit user confirmation, trading convenience for confidentiality.

\paragraph{Authorized-Destination Misuse and Availability.}
Destination binding restricts \emph{where} a secret can be resolved, but cannot prevent an injected agent from executing an unwanted action \emph{inside} a legitimate destination (e.g., selecting an adversary's beneficiary account inside a banking app prior to resolving an OTP). While task tokens, transaction summaries, and Android Protected Confirmation mitigate this risk, full semantics require application cooperation. While policy mismatches reject without decrementing the single-use budget (preserving availability against naive redirection), an adversarial agent could attempt brute-force exhaustion or repeated invalid attempts; \SH{} counters this with a bounded retry threshold ($k_{\max}=3$) before revoking the handle.

\paragraph{UI Compatibility, Segmented OTPs, and Model Drift.}
Fintech apps often divide codes across six single-digit \texttt{EditText} fields or custom canvas views (Flutter/React Native). \SH{} resolves segmented inputs by inspecting the container's sibling hierarchy, auto-populating sibling nodes to avoid fragmented typing. For custom canvas views lacking accessibility semantics, \SH{} safely fails closed, requiring direct user touch confirmation. While tested on Android~14 against Mobile-Agent v3.5 (Sonnet 4.6), the capability guarantees anchor security in the OS boundary.
