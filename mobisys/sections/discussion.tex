\section{Discussion and Limitations}
\label{sec:discussion}

\paragraph{Deployment Roadmap and AOSP Upstream.}
While evaluated on stock Android~14 via a user-granted Notification/Accessibility APK (\texttt{b3secrethandle.apk}) paired with an isolated SDK bridge, \SH's target architecture (\S\ref{sec:design}) integrates upstream into AOSP \texttt{system\_server}: (1)~\textbf{Input Dispatch:} The \texttt{Resolver} hooks into \texttt{InputDispatcher} and \texttt{ViewRootImpl}, injecting secrets into private text buffers without accessibility exports or overlay delays. (2)~\textbf{Hardware Keystore Root:} Keys reside in TrustZone/StrongBox, preventing offline key extraction even if device storage is compromised (online root compromise remains out of scope per \S\ref{sec:threat}). (3)~\textbf{Unified Service:} Mint points and Vault consolidate into a native, SELinux-confined \texttt{SecretHandleManagerService}.

\paragraph{Memory Hygiene, Cross-Device Use, and Transparency.}
Upstream native services pin secrets via \texttt{mlock()} and zero buffers via \texttt{explicit\_bzero}; the evaluated Java \texttt{Vault} isolates entries within its own process boundary away from the unprivileged agent UID (acknowledging JVM \texttt{String} GC limits). For manual cross-device typing, users can tap the notification to authenticate biometrically (\texttt{BiometricPrompt}) and view digits in a \texttt{FLAG\_SECURE} dialog unexposed to screenshots or accessibility. For anti-bot SDKs, resolvers emit an \texttt{AttestedResolutionReceipt}. All experiments use synthetic canaries and open benchmarks (Apache 2.0; Appendix~\ref{sec:artifact}). LLM tools were used solely for language proofreading; all designs, proofs, and measurements were produced by the authors.

\paragraph{Limitations and Threats to Validity.}
\label{sec:limitations}
\emph{Platform Scope and Adaptive Races}: Stock Android~14 evaluation grants \texttt{b3secrethandle.apk} notification-listener and accessibility capabilities while confining the untrusted agent to a separate unprivileged UID. On unmodified OSes, \texttt{SecretBrokerService} relies on regex extraction after notification posting and \texttt{RedactionAccessibilityService} tracks bounds via 200\,ms/event scans; rapid scroll or arrival before overlay commit poses a finite race mitigated only by SDK bridge render synchronization. Figure~\ref{fig:b3}(b) masks the full SMS bubble conservatively (trading transaction context for zero-leak safety; span-level masking is future work). Fallback touch dialogs must set \texttt{setFilterTouchesWhenObscured(true)} to resist tapjacking. Compromised kernels and OEM debug channels lie outside our trust model.
\emph{Web Views}: Package identity cannot enforce document origins inside WebViews; binding web forms requires Chromium origin attestation, falling back safely to fail-closed rejection.
\emph{Authorized-Destination Misuse}: Destination binding restricts \emph{where} secrets resolve, not semantic actions \emph{within} legitimate apps. Repeated invalid attempts are throttled by retry bound $k_{\max}=3$ before falling back to local touch confirmation, thwarting DoS depletion.
