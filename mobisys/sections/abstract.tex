Mobile GUI agents must often use a one-time password, credential, address, phone number, or payment identifier to finish a task. Today the value is placed in a screenshot, accessibility tree, prompt, or action argument, so an injected instruction can convert task authority into disclosure or redirection. We present \SH, an Android design for \emph{usable but invisible} secrets: a privileged service mints an opaque, authenticated handle at the authoritative OS source---the SMS or notification OTP pipeline, Credential Manager, the clipboard, or a wallet---before the raw value can reach the agent. The handle binds a secret type, a task identifier, a destination predicate over package, WebView origin, and field class, and a type-specific lifecycle (single-use and TTL for OTPs, task-scoped for identifiers, confirm-per-use for payment). The agent observes only the handle and issues \texttt{ENTER(handle)} toward a UI node; the OS resolves the value only after authenticating the handle, validating task and target, enforcing expiry/use/confirmation, and reserving the handle against races, then redacts the resolved field from subsequent agent observation. We report an on-emulator reproduction of the OTP-forwarding attack and a labeled, \emph{simulation-only} reference-model study whose trends motivate the design; they are not device measurements and are not presented as paper results. We close with a preregistration-style evaluation plan (killer experiment, attack families, and baselines) for the full system.
